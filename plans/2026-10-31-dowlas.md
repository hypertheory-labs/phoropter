# phoropter-tui moves in, as `tui/`, and still reads only what phoropter serves

Phoropter-tui is a terminal reader of phoropter's pages, built over two days in its own
repository. It's been a second reader of the profile, and it found the gaps selvage and
osier closed. It plans its own work in this format. Six of its plans have landed, among
them ramie (reading the draft), batiste (answering from the TUI), and nankeen (landed
plans aren't edited from the TUI). Every time one of its plans needed a reason from
phoropter, it could only cite it in prose: "loden says", "sorrel declined". Every time
phoropter needed something from it, the request went through a brief,
`for-phoropter.md`, carried between repositories by hand. Both are what two
repositories cost. In one repository they're anchors and drafts.

Other people's readers still build against the public API, the served pages, and send
pull requests. This one is first-party, the way a CLI lives with the service it reads.

## Decision: The TUI comes in with its history, under `tui/`, and its plans join `plans/`
- where: `CLAUDE.md`
- quote: `Jeff may build a TUI on them, in another`

**Because (Jeff):** "declines, etc. here should point at things from that repo." In
phoropter-tui, one commit moves everything under `tui/` except `plans/`. Then this
repository merges it with `git merge --allow-unrelated-histories`. Commits keep their
SHAs, so every `base:` and `head:` in the TUI's plans still names a commit here. The
plan names don't collide with phoropter's. CLAUDE.md's "in another repo" changes to
`tui/`.

## Decision: Plans from both sides can point at each other
- where: `plans/2026-10-30-gimlet.md › Cross-repo anchors are shown as text`

**Because (Claude, not asked):** gimlet showed cross-repo anchors as text, since v0 reads
one repository. That stays true. The TUI coming in is what makes its references
resolve. A TUI plan can anchor a phoropter entry and `revisits:` one, and phoropter's
pages list TUI entries under "anchored by". The next TUI draft is the first case: it
revisits loden (the one draft, at the root). Jeff found more evidence while this was a
draft: the TUI, run from phoropter-tui, couldn't answer it, because it looked for the
draft in its own repository.

## Decision: The brief becomes drafts and shelf seeds
- where: `plans/2026-10-30-gimlet.md › A separate brief beside the plan`

**Because (Jeff, then Claude):** gimlet declined a separate brief because "two copies of
what to build can disagree." `for-phoropter.md` is one. Its open items become seeds in
`shelf/`, each restated into a draft when it's picked up:
- `›` paths resolving (`new-never-resolved`, `where-path-unresolved`, `view-no-code`)
- file pages (ranges, symbol anchors on their file, a place lookup, the blob id)
- what's already at a draft's places, whose condition is met
- reasons to re-check, and `Holds while:`
- a Select's chosen options as properties
- where indexing lives, with a plugin for each language

The brief stays in `tui/docs/` as the record of what the second reader found, marked as
superseded by `shelf/`.

## Decision: The TUI reads only what phoropter serves, and the rule says why
- where: `CLAUDE.md`
- quote: `**The rels and microdata are a public API.**`

**Because (Jeff and Claude):** the TUI found the profile's gaps because it could read
nothing else, and its gaps ledger only works while that's true. `tui/CLAUDE.md` says
the TUI is tested only against served or built pages. It never reads `src/`, and never
imports or shells out to phoropter's code beyond running its dev server. Go and
TypeScript can't import each other by accident, which helps. When the ledger goes quiet,
it should be because phoropter closed a gap, never because the TUI started reading past
the pages.

## Decision: Two CLAUDE.md files, the root one pointing at the TUI's
- where: `CLAUDE.md`
- quote: `**Claude commits; Jeff pushes.**`

**Because (Claude, not asked):** a session in `tui/` needs the TUI's rules (the boundary,
the ledger, the Go dependency pins). A session at the root needs to know the TUI is a
reader whose gaps are phoropter's to close. The root file gets one line saying so and
pointing at `tui/CLAUDE.md`. The TUI's file drops its "never edit `../phoropter`" rule,
since it's here now. Its boundary is the public API, not the directory.

## Decision: Each side keeps its own tests
- where: `package.json`
- quote: `"test": "node --test test/"`

**Because (Claude, not asked):** someone sending phoropter a pull request shouldn't need
Go installed. `npm test` stays phoropter's, and `go test ./...` in `tui/` stays the
TUI's. The TUI's fixtures are sites built by phoropter, and when the profile changes
they're rebuilt in the same work, which is what being one repository is for. `npm test`
doesn't run the TUI's tests even when Go is installed: two commands, each side's own, and
a change to the profile names both in its plan (Jeff).

## Decision: The lineage copies come to the root
- where: `.gitignore`
- quote: `.loom/cart/`

**Because (Jeff):** phoropter-tui keeps `.loom/` committed (copies of the annotating and
cart agreements this work descends from), with `.loom/cart/` ignored. Phoropter already
ignores `.loom/cart/` and restates the same annotating agreement. The copies describe
the whole repository's lineage, not the TUI's alone, so `.loom/` moves to the root
rather than under `tui/`. Nothing in either side references `.loom` paths, as both
CLAUDE.md files say. The other choice was `tui/.loom/` (Jeff).

## Decision: phoropter-tui's own repository is archived, pointing here
- where (new): `tui/README.md`

**Because (Claude, not asked):** two live copies can disagree, for the same reason as the
brief. After the merge, the old repository's README says where the TUI lives now, and
Jeff archives it on GitHub. Jeff pushes. Nothing here changes a remote.

## Decline: Rewriting the TUI's plans for their new paths
**Because (the guide):** plans are read as written. The TUI's plans anchor
`internal/tui/screens.go` and the like. At their base commits those paths are right, and
they resolve. At the generated commit they've moved to `tui/internal/…` and show as
`no-file`. That's true: the files moved. A later TUI plan anchors the new paths.

## Decline: One language for both
**Because (Claude, not asked):** the TUI is a reader of the public API, and a reader in
a different language than the server is the strongest proof the API is public. It's
Go, with Bubble Tea, because that's what a terminal reader is good in. Rewriting it to
share code would undo the reason it's worth having here.

## Guess: The TUI stays an outside reader inside this repository
**Disproved if:** a change to the TUI reads `src/`, imports phoropter's modules, or
closes a gap in the TUI's ledger without phoropter's pages changing.
