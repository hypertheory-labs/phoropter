# A first symbol anchor works on Windows, and phoropter says how to get there

The trial (`shelf/trial.md`) found three things standing between a newcomer and their
first symbol anchor. All three are bugs in phoropter, not judgment calls, and each one
sent the trial's agent somewhere wrong. Asked to anchor a symbol, the agent declined to
install an indexer because `doctor` said none was needed. Then, with the indexer from
Jeff's clone, a bare `src/main.ts` came back "no named declarations". And once it had a
package, every symbol looked missing on Windows. The agent got past all three and
patched the third in the VM's clone. The fixes belong here.

## Decision: The TypeScript indexer writes paths with `/`
- where: `indexers/typescript/index.ts`
- quote: ``definitions[key] = [prefix ? `${prefix}/${doc.relative_path}` : doc.relative_path, r[0] + 1, (r.length === 4 ? r[2] : r[0]) + 1];``

**Because (the trial's agent, then Claude):** on Windows, Node's `relative()` and
scip-typescript's `relative_path` both use `\`, and the contract says `/`
(`indexers/README.md`). So phoropter looked for `src\main.ts`, found no such file, and
every symbol was missing. The Go indexer already converts with `filepath.ToSlash`. This
converts the platform's separator, so nothing changes where it's already `/`.

## Decision: `--check` names a backslash path for what it is
- where: `internal/site/check.go`
- quote: `say(fmt.Sprintf("%s isn't a file at %s; paths are relative to the repository's root", file, repo.Short(sha)))`

**Because (Claude, not asked):** `--check` would have caught the bug, but as "isn't a
file at HEAD", which sends whoever reads it looking for the wrong thing. A path with
`\` gets its own message: the contract's paths use `/`, and on Windows that means
converting. Phoropter keeps the contract strict rather than quietly accepting `\`,
because silent tolerance here is how the next indexer ships the same bug.

## Decision: `symbols` says how to get the indexer a file needs
- where: `main.go`
- quote: `fail(fmt.Sprintf("no indexer here handles %s files. phoropter doctor says what this repository needs.", ext))`

**Because (Claude, not asked):** this was a loop. `symbols` sent the agent to `doctor`,
and `doctor` counts only the symbols plans already anchor, so in a new repository it
said "no indexer is needed yet". The agent took that at its word, which was reasonable,
and declined the indexer. Now `symbols` gives the fix itself, the same line `doctor`
would give for that language: `go install` for Go, a clone for TypeScript. For a
language phoropter doesn't ship an indexer for, it points at `indexers/README.md`.

## Decision: `doctor` says how to start anchoring symbols, when nothing anchors one yet
- where: `doctor.go`
- quote: `"File anchors with a quote work in any language.\n")`

**Because (Claude, not asked):** the other half of the loop. "No indexer is needed yet"
is true, and it was read as "don't bother". One more line says that `phoropter symbols
<file>` lists what can be anchored in a file, and what it needs when it can't.

## Decision: "Nothing defined" says when the indexer found no packages at all
- where: `main.go`
- quote: `return msg + "it has no named declarations (top-level statements, say); a file anchor with a quote reaches it"`

**Because (the trial, then Claude):** a bare `src/main.ts` has a named function, so "no
named declarations" was false. The real reason was that the TypeScript indexer indexes
packages, and there was no `package.json` with a name. When an indexer returns no
packages at all, the message says so, and for phoropter's own indexers it says what a
package is: a `go.mod` for Go, and for TypeScript a named `package.json` with a
`tsconfig` beside it. Jeff's answer to the bigger question: a new repository's first
real plan is usually how it builds, which is `init`'s template's business, in its own
plan.

## Decline: Accepting `\` in indexer output
**Because (Claude, not asked):** phoropter could convert the paths itself and the bug
would vanish. But every reader of the index store would then need the same tolerance,
and an indexer author on Windows would never learn their output is wrong. The contract
is the thing that's shared, so it stays strict, and `--check` explains it.

## Guess: A newcomer with a TypeScript file reaches a symbol anchor without asking
**Disproved if:** on a fresh repository, with a `.ts` file and the clone, following only
what `symbols` and `doctor` print doesn't get to `phoropter symbols` listing that file's
symbols.
