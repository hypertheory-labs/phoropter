# phoropter becomes one Go binary, with the TUI inside and indexers outside

Gimlet (phoropter's first version) chose TypeScript to "start where SCIP indexing is
strong": phoropter ran scip-typescript in its own process. Asked in gimlet's frame: does
that still decide phoropter's language? What moved is the code. Seersucker (indexers are
programs in `indexers/`) took indexing out of phoropter. scip-typescript now runs only
inside the TypeScript indexer, a separate program. The core that's left (about 2,300
lines) reads git, parses plans, resolves anchors, renders HTML, keeps the index store,
and serves. Nothing in it needs TypeScript anymore.

Jeff: "I *really* like the idea of installing one binary." The TUI is already Go, and
already twice phoropter's size. One Go binary holding phoropter and the TUI is one
install, no Node for anyone whose repositories don't need the TypeScript indexer, and one
language to work in. It's cheapest now, before more is written in TypeScript.

## Decision: phoropter is rewritten in Go, and the TypeScript is deleted in the same work
- where: `plans/2026-10-30-gimlet.md › TypeScript, indexing with scip-typescript at the generated commit`

**Because (Jeff, then Claude):** gimlet's reason was in-process indexing, and seersucker
removed it. The rewrite lands whole: the Go version replaces the Node one completely,
with no stretch of running both, and `src/` is deleted when the Go version builds the same
sites. The commands stay as they are (`phoropter`, `build`, `index`, `url`, `symbols`,
`index --check`), with the same behavior and output.

## Decision: Done means the same sites, with structure identical and prose close
- where: `src/render.ts`
- quote: `import { marked } from 'marked';`

**Because (Jeff and Claude):** the site's HTML is the public API, so it's how the rewrite is
checked. Before any TypeScript is deleted, the Node version builds golden sites:
mock-control at `f02528f`, phoropter at the plan's base, and the TUI's fixture repositories.
They're committed as fixtures, and the Go version's tests build the same commits and
compare them by their microdata, not their bytes. Both versions of each page are parsed
with the TUI's microdata parser, and every page must have the same items, properties,
text values, `rel` links and paths, with every entry's slug the same, since slugs are
URLs, and URLs are the API. Bytes would differ for no reader's sake: the two markdown
libraries escape and wrap differently. The rendered prose inside a reason may differ
where goldmark renders an edge case differently ("close is probably enough", Jeff:
nothing reads prose but a browser). The as-built lists every difference the comparison
finds. Claude's confidence, asked by Jeff: goldmark as the library 0.9, structure
identical on the golden sites 0.8, the plan landing whole 0.75, mostly for the effort.

## Decision: Markdown is parsed with goldmark, and plan structure is phoropter's own
- where: `src/plan.ts`
- quote: `import { lexer, type Tokens } from 'marked';`

**Because (Claude, not asked):** goldmark is Go's CommonMark library, with an AST to walk the
way `src/plan.ts` walks `marked`'s tokens. What phoropter decides from that AST is
phoropter's: where entries start, their kinds and titles, their anchor lists, the bold
lead's source, prompts and their fallbacks, slugs. The golden sites hold it to the same
answers. The rule that code spans unwrap the CommonMark way already matches goldmark.

## Decision: The TUI is inside the binary, as `phoropter ui`, and a test keeps it outside phoropter
- where: `tui/CLAUDE.md`
- quote: `- **The boundary: the TUI reads only what phoropter serves.** It's tested against`

**Because (Jeff, then Claude):** one binary means the TUI ships in it. `phoropter ui` starts
the TUI against the server it finds with `phoropter url`, or starts one. The TUI's boundary
has been a rule in a CLAUDE.md: it reads only the served pages. In one module it becomes a
test, which fails the build if any package under the TUI imports one of phoropter's own
(the site, the renderer, the store). The TUI still reaches phoropter over HTTP only, so
its gaps ledger stays honest, and a third-party UI on `PATH` gets nothing the built-in one
doesn't. A second binary shipped beside it, and a separately installed UI, were weighed:
a separate binary only keeps the TUI from importing phoropter by making it inconvenient,
and the test enforces it (Jeff: go with the fallback).

## Decision: One Go module at the root
- where: `tui/go.mod`
- quote: `module phoropter-tui`

**Because (Claude, not asked):** one binary is one module. `tui/` becomes packages inside it,
and its own `go.mod` goes. The TUI's dependency pins (Bubble Tea v1.3.4, lipgloss v1.1.0,
`charmbracelet/x/ansi` v0.8.0) were set for Go 1.24, and Go 1.27 is installed now. They're
checked again, and kept or moved with the TUI's tests passing. The Go indexer keeps its own
module in `indexers/go/`, since it's a separate program.

## Decision: Indexers stay programs, so the TypeScript one keeps Node
- where: `package.json`
- quote: `"marked": "18.1.2"`

**Because (seersucker):** an indexer is any program that prints the contract's JSON.
`indexers/typescript/` runs scip-typescript, which is Node, so it stays a Node program.
`package.json` keeps only what it needs. A repository with no TypeScript symbol anchors
never runs Node at all. `marked` goes.

## Decision: Install is `go install`, for now
- where: `README.md`
- quote: `ln -s "$PWD/src/cli.ts" ~/.local/bin/phoropter   # any directory on your PATH`

**Because (Claude, not asked):** `go install github.com/hypertheory-labs/phoropter@latest`
gives one binary with the TUI in it. Release builds, Homebrew and a short name are the
shipping plan's. The README's install section changes to this, and the agent block
doesn't change.

## Decline: Rewriting the TypeScript indexer in Go
**Because (Claude, not asked):** it exists to run scip-typescript, which is Node. A Go
TypeScript indexer would be a different indexer, not a port of this one.

## Decline: Running the Node and Go versions side by side for a while
**Because (Jeff's rule):** a plan lands whole. A stretch with two phoropters is two copies
that can disagree, the same reason gimlet declined a separate brief. The golden sites do
the comparing, before the switch.

## Guess: The Go version builds every golden site with identical structure
**Disproved if:** after the rewrite, any golden site differs in a microdata property, a
`rel`, a page path or a slug, beyond what the as-built lists and explains.

## Guess: A Go repository needs nothing installed but the binary and scip-go
**Disproved if:** on a machine without Node, `go install` and then `phoropter` in this
repository's `tui/` fails to serve its plans with Go symbol anchors resolved, or `phoropter
ui` fails to open them.
