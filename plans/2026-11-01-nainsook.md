# Links out of the TUI: copy where you are, or open it

Jeff, reading in the TUI, wants to hand what he's looking at to someone else: "heya, look
at this" to the agent, or the browser for a longer read. Today he'd have to work out the
URL himself. This is the smallest of the next steps Jeff ranked (linking, then lenses,
then file mode), and it's the first piece of the lens format, since a lens is a list of
the references this copies.

## Decision: `y` copies the address of what you're on
- where: `tui/app/tui.go`
- quote: `refresh() (forget []string, at string)`

**Because (Jeff):** "copy a link into the clipboard I could hand the agent". On a plan it's
the page with the entry's fragment
(`…/plans/burlap/#the-verdict-is-the-answer-s-first-word-…`), on the plan list the
chosen plan, on a place its page. Every screen says what "here" is, the way each already
says where to land after a refresh, and one key handles all of them. `y` is vim's yank.

## Decision: `Y` copies the reference instead
- where: `guide.md › Working with plans › 1. Write the plan › Anchors`
- quote: ``  - **Another plan's entry:** `plans/<file>.md › <entry title>`.``

**Because (Claude, not asked):** a `localhost:4175` link only lives as long as that server,
on that port. That's fine for the agent next to you, and broken in a ticket. The
reference, `plans/2026-10-31-burlap.md › The verdict is the answer's first word…`, is
durable, an agent can resolve it from the repository alone, and it's the syntax a plan's
`where:` already uses. It's also one line of a lens (`shelf/lenses.md`). A draft's entries
have no reference until the draft lands, so `Y` says that.

## Decision: `b` opens it in the browser
- where: `tui/app/screens.go`
- quote: `return "j/k move · enter open · o oldest/newest first · r refresh"`

**Because (Jeff, then Claude):** Jeff asked to "open the browser at that entry". `o` would
match the server's menu, but in the TUI `o` already flips the plan list's order, and one
key meaning two things on neighboring screens is worse than a new one. `b` is free on
every screen.

## Decision: The clipboard gets OSC 52 and the system's own command
- where (new): `tui/app/links.go`

**Because (Claude, not asked):** OSC 52 is an escape sequence the terminal turns into a
clipboard write. It works in Ghostty, through tmux, and over ssh, and its library is
already in the module graph by way of the TUI's dependencies. But Terminal.app ignores
it, silently. So the link also goes to `pbcopy`, `wl-copy` or `xclip`, or `clip`, when
one is there. Copying twice to the same clipboard is harmless. The status line says what
was copied, so a copy that didn't arrive is easy to spot.

## Decline: A URN for every plan and entry, resolved by the server
**Because (Jeff, joking, and Claude):** `http://localhost:{port}/by-urn?urn=…` was the
thing Jeff said he'd ask for next. The reference already is a name for an entry that
doesn't depend on a server. A dev-server endpoint that turns a reference into a page may
make sense once lenses exist and something needs to follow one. Until then it would be
an address scheme with one user.

## Guess: `y` reaches the clipboard in Ghostty and in Terminal.app
**Disproved if:** after `y` on an entry, pasting in either terminal doesn't give the
entry's URL.

## Guess: An agent handed a copied link or reference finds the entry with nothing else said
**Disproved if:** given only the URL, or only the reference, an agent lands on a different
entry, or has to ask which one was meant.
