# A page says when HEAD couldn't be built

Following HEAD, the dev server rebuilds when a commit lands. When the rebuild fails, it
keeps serving the last site that built and says so on stderr, once. In the trial
(`shelf/trial.md`), a plan's anchor stopped the build on Windows, and the server sat at
an old commit while the agent and Jeff read pages that looked current. Dupioni made that
cause impossible, but the shape remains: a failed rebuild is visible only to whoever is
watching the server's terminal, and when an agent runs it in the background (the
first plan's default), nobody is.

## Decision: Every page the dev server sends says HEAD couldn't be built, and why
- where: `internal/site/serve.go`
- quote: `fmt.Fprintf(os.Stderr, "phoropter: couldn't rebuild at %s, still serving %s: %v\n", l.o.Repo.Short(sha), l.site.Generated.Short, err)`

**Because (the trial, then Claude):** the reader is who needs to know, and the page is
what both readers read. A notice under the header says HEAD is at the commit that
failed, the error, and that this page is from the last commit that built, with how to
try again: a new commit, or `r` and enter at the server's terminal. It goes on every
HTML page the server sends, the draft and lenses included, the same way the draft link
is added: built pages don't know, and the server does. A built site never has it,
since `phoropter build` fails outright instead.

## Decision: The notice is microdata, named in the profile
- where: `internal/site/profile.go`
- quote: ``{`noteCount`, `On the home page as the dev server serves it, on a plan with notes in <code>drafts/</code>: how many (tarlatan; organza renamed it from <code>requestCount</code>).`},``

**Because (Claude, not asked):** an agent reading pages is the reader most likely to
miss a sentence and trust the header's commit. A `stale` item with `commit` (the HEAD
that failed, full sha in `value`) and `error` lets any reader check for it without
parsing prose. It's an addition to the public API, so the profile says what it is.

## Decision: The notice goes when a build succeeds, or HEAD comes back
- where: `internal/site/serve.go`
- quote: `if force || (sha != "" && sha != l.site.Generated.SHA && sha != l.failed) {`

**Because (Claude, not asked):** a later commit that builds clears it, as does a forced
rebuild. So does HEAD moving back to the commit being served, say after a reset, since
the page is then current again. Otherwise the server would announce a failure about a
commit nobody is on.

## Decline: Retrying a failed commit on its own
**Because (Claude, not asked):** the server doesn't retry the commit that failed, so it
isn't rebuilding every second, and that stays. A cause that isn't in the commit, like a
missing indexer, is fixed and then retried with `r`, which the notice names.

## Decline: Teaching the TUI to show it in this plan
**Because (Claude, not asked):** the TUI reads only the profile, and once `stale` is in
the profile the TUI can show it in its own plan. Until then, the TUI reads pages
whose header is honest about their commit, as it does today.

## Guess: Nobody reads a stale page as current again
**Disproved if:** a person or an agent works from a page served while HEAD couldn't be
built, without noticing it was the older commit.
