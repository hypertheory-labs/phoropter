# As built: percale

Built as planned, plus one change the first agent-written lens called for. Lenses live in
`drafts/lenses/`. The dev server serves `lenses/` and each lens. The TUI lists them (`L`),
filters a lens (`f`), and collects with `+`. The README's agent block says how to make
one. `go test -count=1 ./...` passes.

Two lenses are in Jeff's `drafts/lenses/` now, neither committed. `try.md` ("Verdicts")
is the one Claude made while building. `dev-server.md` is the one an agent wrote to test
the first guess. Keep, edit or delete them as you like.

Jeff's thoughts while this was built went to the seeds. In `shelf/init.md`: the dev
server's run-time layer is where per-repository recipes for the agent could be served.
In `shelf/lenses.md`: a lens with a note is a way to start a conversation.

## Changed: A lens line may put the entry's kind before its title
- where: `internal/site/lens.go`
- quote: `if e.Title == title || (e.Kind != "" && title == e.Kind+": "+e.Title) {`

**Because (measured, then Claude):** the agent asked to mark plans wrote 25 lines. All 19
Decisions it wrote as bare titles, as the format says, but all six Declines and Guesses
as `Decline: …` and `Guess: …`, the way every page shows them. Those six didn't resolve.
Asking every reader and agent to remember that the kind is left out would keep costing
something. A kind in front is accepted only when it's the entry's own kind, so it never
picks the wrong entry. This is lenses only. Whether a plan's `where:` should accept the
same thing is a format question for Jeff, since the guide defines that syntax.

## Chose: The dev server links `lenses/` from every page, even with none
- where: `internal/site/serve.go`
- quote: `// Always, so a reader can start a lens before there is one.`

**Because (Claude, not asked):** `+` needs to find the lenses page to offer the lenses
there are, and the TUI never guesses a URL. With no link until a lens existed, the first
`+` couldn't work. The empty page says how to start one.

## Chose: A lens page says it's a lens by its `itemCount`
- where: `tui/substrate/lens.go`
- quote: `func IsLens(p *Page) bool   { return p.Main.Get("itemCount") != nil && p.Main.Get("entry") == nil }`

**Because (Claude, not asked):** the TUI picks a screen by the main item's properties, and
a lens has a `title` like a plan does, so it was opening as one. Plans have no
`itemCount`, so that tells them apart without a type.

## Chose: An answered entry in a lens shows its verdict
- where: `internal/site/lens.go`
- quote: `if it.Entry.Kind == "Answered" && it.Entry.Verdict != "" {`

**Because (Claude, not asked):** the plan said a guess shows its verdict or "open". An
as-built's `Answered:` entry has a verdict too, and a lens holding it would otherwise
hide the most useful word.

## Chose: The served golden comparison skips the new `lenses` link
- where: `internal/site/golden_test.go`
- quote: `// lenses link came after the golden pages were made (percale).`

**Because (Claude, not asked):** the golden pages predate lenses, so every served page now
has one extra link. Skipping exactly that link keeps the Node-made golden pages as they
were, rather than regenerating them from the Go version they're meant to check.

**Answer (an agent, measured):** disproved, then fixed. A fresh agent with only the agent

behaves". Its 25 lines were well chosen, and it reasoned about runtime versus static
build on its own. Six didn't resolve, all because of the kind in front of the title.
With the change above, all 25 resolve, on the same file, unedited.
