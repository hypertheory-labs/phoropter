# `phoropter init`: a repository's first plan, as a draft

Today a repository learns how to work with plans from a block pasted out of the README
into its `CLAUDE.md`. The block has nearly doubled since it was first written, and the
course repository still holds a copy from before lenses, with nothing saying it's old. A
pasted block goes stale silently. The seed for this (`shelf/init.md`, deleted when it
was drafted) collected the layers that should replace it. This plan builds the smallest
version that does: a pointer that can't go stale, and a first plan that holds the
conventions, so changing them is a revisit with a reason. The first plan is the
repository's default working agreement (Jeff), and it should feel like something done
*for* the people in it, not *to* them.

The class's `plans/` folder showed something the seed didn't have (Jeff, from the .NET
course that ended 2026-11-18). There, Jeff named the approaches out loud before anything
was built, the class built one, and an agent wrote the record afterwards, as review.
Three things came from that: a first plan is addressed to a reader; the agent should
name the roads not taken; and in a repository that already has code, the pair can look
back at what was already decided.

## Decision: `phoropter init` writes the first plan as a draft, on purpose
- where: `main.go`
- quote: `case "build", "index", "url", "symbols", "ui", "indexers", "guide", "help", "-h", "--help":`

**Because (Jeff and Claude):** `init` writes into a repository, so it's run on purpose,
as `phoropter index` is (batik's rule: phoropter writes only when asked). It writes
`drafts/plan.draft.md`, from a template built into the binary the way the guide is. The
first round with the agent is working that draft, and converting it makes the first plan
(`tui/docs/next.md` §4). If a draft already exists, `init` says so and writes nothing,
since a repository has one draft.

## Decision: The first draft holds the conventions, each with its default as the fallback
- where (new): `init.md`

**Because (Jeff and Claude):** a convention written as a Decision can be argued with and
revisited, but one pasted into `CLAUDE.md` can't. Each is a Decision with a prompt whose
fallback is today's default, so a pair that says nothing gets what the README's block
says now. That's what "silence means proceed" is for. The template holds:

- **Who reads drafts here, and when one goes up.** Default: when the agent's confidence
  or the shared understanding is thin. A junior might want a draft for nearly
  everything, and Kernighan rarely. The guide leaves this to the pair, and this is where
  the pair says it.
- **A draft is pitched to its reader; the plan is written for whoever comes later**
  (Jeff). The draft can explain, ask, and meet the person where they are. Converting
  takes the pitch out, and what lands reads to someone who wasn't there.
- **The agent names an approach not taken, sized to the work.** For auth, several
  Declines. For a one-line fix, a single line: "asked for other approaches: none better,
  because…" Never a strawman, as the guide already says.
- **The agent offers; nothing gets stamped** (Jeff). "Want to look at this draft?",
  "I think we can skip the draft, here's the plan", "Want to have a look, or should I
  just do it?" It's the way you'd talk in chat anyway, and the way an agent offering
  "maybe we should make a cart for this?" feels done for you, not to you. The agent
  isn't the format's cop. A pair that skips a draft hasn't broken anything.
- **Wondering isn't asking.** When the person says "just thinking about it", the agent
  answers and doesn't act. That gap is where "you could, but I wouldn't, and here are
  three CVEs" comes from (Jeff's homelab example, from the class's lunch break).
- **The rest of today's block, as conventions:** the agent starts the server, writes a
  plan before non-trivial work, writes the as-built after, checks `drafts/` for notes at
  the start of a session, uses lenses, and has no veto.

Whatever the guide already says, like never editing a landed plan or how a draft
converts, stays in the guide, and the template points there.

## Decision: The first draft opens with a note to the person, in the agent's voice
- where (new): `init.md`

**Because (Claude, from the class's `human-prompt.md`, then Jeff):** every layer in the
seed speaks to the agent. The class's companion note was the agent telling the human
what it can't know: their organization, their team, its history, the real goal behind a
ticket. Two or three sentences of that change the agent's answers more than anything
else does. The draft's opening says it, and because the opening survives conversion,
the first plan says it to the next person to join too. It's in the agent's voice, as in
the class. Jeff, of that note: "it's very honest, and direct, and establishes a sort of
partnership."

## Decision: `init` prints a pointer to paste, and doesn't edit `CLAUDE.md`
- where (new): `main.go`

**Because (Claude, not asked; then Claude, unanswered, so its fallback):** the pointer is
two or three lines. This repository records decisions as plans, `phoropter guide` prints
the format, and the first plan (or its draft) says how we work here. Only the pointer is
pasted, so only the pointer can go stale, and it names nothing that changes. Editing
someone's agent instructions is a bigger write than a draft in a gitignored folder. So
`init` prints the pointer and says where it would go, even when a `CLAUDE.md` or
`AGENTS.md` exists.

## Decision: `init`'s output walks the person through the first round
- where (new): `main.go`

**Because (Jeff and Claude):** the pointer is the agent's version of `.loom/orientation.md`:
a few lines pointing at rules that live somewhere that can't go stale. Nothing does that
for the person. Today they learn it from the README, which is the copy we're trying to
stop people pasting from, and Jeff, who made this, "still gets a little lost". `init` is
the one moment phoropter knows someone is starting, and they're at a terminal. So it
says what just happened, that the first plan is a draft at `draft/`, to open
`phoropter ui` or hand the agent the address, and to annotate whatever you'd change,
since silence means proceed. It's printed by the binary, so it changes only when the
binary does.

## Decision: The README's agent block becomes the pointer, plus `phoropter init`
- where: `README.md › phoropter › Tell your agent`
- quote: `` Paste this into its `CLAUDE.md` (or `AGENTS.md`), and adjust it to taste: ``

**Because (Claude, not asked):** the block's contents move into the template. Leaving
them in the README too would make two copies that can disagree, and the README one is
the one that goes stale.

## Decision: In a repository with history, the first plan invites looking back, later
- where (new): `init.md`

**Because (Claude, then Jeff):** the class's record was written after the work, and it
worked well as review. A repository's earlier choices (its framework, its database, how
it tests) were made before plans existed. Looking back isn't part of the first round,
which stays about how the pair works. Jeff agreed: "this is a big step, I think, and
very real." The template's last Decision invites it: when new work touches code no plan
explains, the agent offers a little archaeology. What is this code in service of? What
plan would have made it this way? If the pair cares, that becomes a plan deciding "we
keep this" (or not), based at that day's commit, with the alternatives as Declines.
That's a decision made now, not one pretended from back then. `init` doesn't automate
it.

## Decision: The guide doesn't change in this plan
- where: `guide.md › Drafts (optional)`
- quote: `Who decides that is the pair's to work out.`

**Because (Claude, not asked; then Claude, unanswered, so its fallback):** the guide is
the format, the same in every repository. Everything above is a convention that a team
can change. Saying in the guide that a draft is pitched to its reader would make that
format. The first plan says it, and the guide can take it up in a plan of its own once a
second repository has tried it.

## Decline: A settings file under `.phoropter/`
**Because (Claude, not asked):** the seed's fifth layer (indexer timeout, which indexer
wins). Nobody is blocked by the environment variable today, and a file read by phoropter
is a bigger thing than this plan needs to show.

## Decline: Agent recipes served by the dev server
**Because (Claude, not asked):** the seed's sixth layer. The template's conventions cover
what the recipes would say for now. Serving them waits until the first plan shows
which ones agents keep missing.

## Decline: A folder of approach files, the way the class did it
**Because (Jeff and Claude):** approaches are how you get to a plan, not part of one.
Phoropter starts where a plan can be drafted. How the pair gets there is theirs: a cart,
a folder of approaches, a whiteboard, a conversation. What phoropter keeps is what
lands, so a road not taken shows up as a Decline, and the naming convention above is
about what the plan records, not how anyone thought it through. `shelf/approaches.md`
holds the rest.

## Decline: A catalog of approaches across repositories
**Because (Jeff and Claude):** "which of our projects used this?" and an agent amending
the catalog with CVEs are real. But phoropter is one repository on purpose, and so are
lenses. Jeff is building it for the class first. It's in `shelf/approaches.md`.

## Decline: `init` as something a UI does
**Because (Claude, not asked):** it's a write into the repository, and writes are
commands run on purpose. A UI can run the command later.

## Guess: An agent with only the pointer works as well as one with today's block
**Disproved if:** in a fresh repository with only the pointer and a converted first plan,
a fresh agent skips something today's block would have it do: plan before the work,
draft when unsure, check `drafts/` for notes.

## Guess: Someone new, given only `init`'s output, reaches the draft and annotates it
**Disproved if:** a person who hasn't used phoropter, in a repository where they've just
run `init`, needs the README (or to ask) before they're reading the draft at `draft/`
and have left a note on it.

## Guess: Looking back happens incrementally, a feature or a defect at a time
**Disproved if:** in a repository with history, under its first plan, the plans that
explain existing code come in a batch someone sets out to write, or never come, rather
than one at a time as work touches that code. (Jeff's guess, from his note on the
draft.)

## Guess: A first draft converted in silence is a valid first plan
**Disproved if:** converting the template with no answers gives a plan that phoropter
shows with an unresolved anchor or a malformed entry, or one that reads as instructions,
not testimony.

## Guess: Naming an approach not taken stays sized to the work
**Disproved if:** given a small fix under the first plan, an agent writes a strawman or a
paragraph of alternatives. Or, given a real choice, it names none.
