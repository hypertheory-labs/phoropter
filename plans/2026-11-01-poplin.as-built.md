## Answered: Following HEAD costs nothing a reader notices
**Answer (Claude, measured):** disproved, on both counts. On phoropter's repository (98
pages, indexes in the store), the first request after a commit took 5.9s, because it
waits for the whole rebuild. Requests between commits went from under 1ms to about
20-25ms, which is the once-a-second `git rev-parse`. Nobody notices the second. The first
is noticeable. The fix is to keep serving the old site while the new one builds and
swap it in when it's ready. Then no request waits, but for those few seconds a page says
the old commit. That changes what this plan decided, so it's Jeff's call, not something
the as-built quietly does.
