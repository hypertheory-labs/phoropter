# Phoropter runs on Windows, as far as the code knows

The trial runs on Jeff's Windows VM. `GOOS=windows go build` succeeds, but reading the
code, three things break there (`shelf/windows.md`), and finding known bugs on the trial
would waste it. This fixes those three, without a Windows machine to test on, so each
fix is one that's right everywhere rather than a Windows branch nobody here can run. The
rest of the seed's list is already handled: the TUI copies with `clip` and opens with
`rundll32` on Windows, and `phoropter symbols` turns a typed path's backslashes into
slashes.

## Decision: A server is alive when its port answers
- where: `main.go`
- quote: `if p, err := os.FindProcess(info.PID); err != nil || p.Signal(syscall.Signal(0)) != nil {`

**Because (Claude, not asked):** `phoropter url` reads each server's record and drops
the ones whose process is gone, by sending it signal 0. Windows has no signal 0, so
every server would look dead and its record would be deleted. Connecting to the
record's port is the same question asked of the thing the agent actually wants, works
on every system, and doesn't touch the server's pages, so it can't start a rebuild. A
refused connection answers at once, so `phoropter url` stays fast.

## Decision: Windows's "address in use" moves to the next port too
- where: `internal/site/serve.go`
- quote: `if o.ExactPort || !errors.Is(err, syscall.EADDRINUSE) || port >= o.Port+100 {`

**Because (Claude, not asked):** Windows reports a taken port as `WSAEADDRINUSE`
(10048), not `EADDRINUSE`, so a second server would fail instead of taking 4174. Both
count now. Retrying on any error would also work, but it would turn a real failure,
like a refused permission, into a hundred attempts and a confusing last error.

## Decision: A checkout is unpacked in Go, with no shell
- where: ``scip-go gomod github.com/hypertheory-labs/phoropter . `github.com/hypertheory-labs/phoropter/internal/site`/Repo#Checkout().``
- quote: ``cmd := exec.Command("sh", "-c", `git -C "$1" archive "$2" | tar -x -C "$3"`, "sh", r.Dir, sha, dir)``

**Because (Claude, not asked):** indexing a commit writes its tree to a temp directory
through `sh -c 'git archive | tar -x'`. PowerShell has no `sh`, so every index of a
commit would fail. Now phoropter reads `git archive`'s output itself, with Go's
`archive/tar`: one less program on every system, not just Windows. An entry whose path
would land outside the directory is refused. A symlink that can't be made, which on
Windows needs a privilege, is skipped rather than failing the checkout.

## Decline: Testing on Windows in this plan
**Because (Claude, not asked):** there's no Windows machine here, and the trial is the
Windows test. What's tested here is what a Mac can test: the checkout matches `tar`'s,
the port check finds a live server and drops a dead one, and `GOOS=windows go vet`
passes.

## Guess: On the trial, phoropter serves, indexes and finds its server on Windows
**Disproved if:** on Jeff's VM, from PowerShell, `phoropter` doesn't serve, `phoropter
url` doesn't print its address, a second `phoropter` doesn't take the next port, or
indexing a commit fails for a reason other than a missing toolchain.
