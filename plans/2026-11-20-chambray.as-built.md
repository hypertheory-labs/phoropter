# As built: chambray

Built as planned. `go test -count=1 ./...` passes, and `GOOS=windows go vet` does. A
test builds a scratch repository whose plan quotes line 4 of a file: `affected` on the
file finds the entry at line 4, and its line reads back as a lens item. A change to
line 2 finds nothing, and a change to line 4 finds the entry. Symbol anchors aren't in
that test, since it has no indexer. On this repository, `affected internal/site/site.go`
found dupioni's two Decisions through their anchor on `placeFor()`.

Jeff, while it was being built: the TUI looking at a place could run this, so printing
is the right default. The TUI reads only served pages (dowlas), so that's the dev
server answering the same question as a page, in its own plan.

## Chose: A quote that's no longer found counts in file mode, and not for a change
- where: `internal/site/affected.go`
- quote: `case gen != nil && gen.Status == "not-found":`

**Because (Claude, not asked):** the plan didn't say. The first run of `--since`
listed chiffon's port check as touched by any edit to `main.go`, because its quote is
code chiffon itself replaced, so it covered the whole file. An anchor whose quote is
gone is on no line, and a change can't touch it. But it's still about the file, so
`affected <file>` lists it, with "though its quote isn't found there now". On
`README.md`, that's four entries: the README drift the documentation seed is about,
found without asking for it.

## Chose: Nothing found prints nothing, and says so on stderr
- where: `main.go`
- quote: `fmt.Fprintln(os.Stderr, none)`

**Because (Claude, not asked):** an empty lens saved by `--out` would be a file
holding no specimens, and stdout stays clean for a reader running it. It exits 0:
nothing anchored is an answer, not a failure.
