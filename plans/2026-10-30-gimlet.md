# Phoropter v0: open one plan and walk it

A static site generated from one repo at one commit: its `plans/`, their as-built
files, and a SCIP index, rendered as HTML with microdata and `rel` links. A person
opens it in a browser and an agent fetches it, and both read the same pages. A small
dev server serves it. The data is mock-control at `90c65b9`, whose only plan is pumice.

This plan is also the brief. Whoever builds it records what changed in
`<this plan>.as-built.md`, and that file answers this plan's guesses.

## Decision: A static site generator plus a dev server, not a running API
**Because (Jeff):** git is immutable, so the site for a commit is a pure function of
the commit and its index. Nothing goes stale; a page is only ever old.

## Decision: The HTML is the API
**Because (Jeff):** the human and the agent should work from exactly the same substrate.
Structure is carried by `rel` links and microdata, not by a separate JSON shape.

## Decision: Read-only
**Because (Jeff):** truth stays in git and markdown. The site is a projection of it,
never a place to write.

## Decision: Every page says which repo and commit it was generated from
**Because (Claude, agreed by Jeff):** "code at HEAD" becomes "code at this commit,"
so a reader can always tell what they're looking at.

## Decision: Each anchor is shown at the plan's base and at the generated commit
- where: `` mock-control: plans/2026-10-29-pumice.md › Selectors use the library's prefix, `mock-panel` ``
- quote: ``- quote: `selector: 'app-mock-panel',` ``

**Because (measured, mock-control at `90c65b9`):** anchors point at the base, and the
plan's own work moves them. Pumice's selector quote matches at its base `da023f1` and
not at `90c65b9`, because pumice renamed it; the README heading moved for the same
reason. Showing only the later commit would make the plan's own work look like drift.
v0 shows both, side by side, and doesn't judge the difference.

## Decision: SCIP anchors resolve through the index; other anchors by their quote
**Because (Claude, agreed by Jeff):** the spike showed `defn_enclosing_ranges` gives a
symbol's line range, so its code is a lookup plus `git show`. Pumice's other anchors
are a markdown heading path and a JSON key path; for those, finding the quote in the
named file is enough to show the code. When it isn't found, the page says so plainly:
"quote not found at `<commit>`."

## Decision: Quote search looks only in the anchor's file
**Because (measured):** searching the whole repo for pumice's quotes matches the plan
itself, which quotes them.

## Decision: `where (new)` anchors are shown, not resolved
**Because (Claude, not asked):** they have no quote by design. Resolving them means
finding where the work landed, which is the drift question, and v0 declines drift.

## Decision: Cross-repo anchors are shown as text
**Because (Claude, not asked):** v0 reads one repo. Lanyard's anchors into pumice
are the first case, and they wait.

## Decision: Reverse pages, one per anchored symbol or file, listing the plans there
**Because (Claude's proposal, unanswered, so its fallback):** the first brick of
level 3, archaeology, and it makes the link graph go both ways from the start. With
one plan each page lists one plan.

## Decision: The first rels, and a profile document that defines them
**Because (Claude, not asked):** v0 can't avoid starting the vocabulary. Registered
rels where they fit (`profile`, `item`, `collection`, `up`); ours are `as-built`,
`anchored-at` (entry to anchor page), and `anchored-by` (anchor page to entry). The
profile document is one page in the site, and each rel's definition says what
question it answers.

## Decision: TypeScript, indexing with scip-typescript at the generated commit
**Because (Jeff and Claude, aide's CLAUDE.md):** start where SCIP indexing is strong.
The spike indexed mock-control in about half a second, so indexing each commit it
needs (the generated one, and each plan's base) is cheap. Libraries and layout are
the builder's call, recorded in the as-built.

## Decision: The generated site isn't committed
**Because (Jeff and Claude):** it's reproducible from the commit, and generated output
in git would bury the plans in diff noise. Output goes to a gitignored directory.

## Decline: A separate client app
**Because (Jeff and Claude):** a second representation would let the person and the
agent see different things. A client, Angular or otherwise, can come later as one more
projection of the same pages.

## Decline: A separate brief beside the plan
**Because (Claude, agreed by Jeff):** two copies of what to build can disagree. Lanyard
designed the plan plus as-built for exactly this handoff, and v0 is its first test.

## Decline: Drift, guesses and triangulation, the heat map, the LSP adapter, the Angular language service, and cross-company queries
**Because (Jeff and Claude):** each was raised, and none is needed to walk one plan.
They're recorded so nobody adds them helpfully.

## Guess: The plan is enough of a brief
**Disproved if:** the builder has to ask for something this plan doesn't say, or the
as-built records a gap that a brief would have filled.

## Guess: Quote search is enough for anchors that aren't SCIP symbols
**Disproved if:** a quote matches more than once in its file at the base, or a reader
can't tell from the page which lines the anchor meant.
