## Chose: Prompts and annotations follow their entry, not their exact place in it
- where: `src/render.ts`
- quote: ``${plan.entries.map((e) => entryHtml(here, plan, e) + extras(e.slug)).join('\n')}``

**Because (Claude, not asked):** the plan placed annotations after the entry holding
their quote; prompts get the same treatment. A prompt is taken out of its entry's
markdown and shown after the entry's reason, which is where a draft's prompts sit
anyway. A note with no quote, or whose quote is gone, comes first.

## Chose: Notes count as current when they match annotations.nvim's own hash
- where: `src/draft.ts`
- quote: ``const current = !!annotates && [source, source.replace(/\n$/, '')].some((v) => sha256(v).startsWith(annotates));``

**Because (measured):** the plan said the page shows the notes' hash, so an annotation
can say which version it answered. The notes file already says which version of the
draft it annotates, `annotates: plan.draft.md sha256:…`, so the page compares that
instead and says when the draft has moved since. annotations.nvim hashes the buffer's
lines joined by newlines (its `sha_of`), which drops the file's final newline; hashing
the file as-is would have called every note out of date.

## Chose: A restated prompt in the notes is its answer, matched by kind and exact text
- where: `src/draft.ts`
- quote: `const prompt = restated && all.find((p) => p.kind.toLowerCase() === restated[1].toLowerCase() && p.text === restated[2].trim());`

**Because (Claude, not asked):** the agreement says an answer restates the question so
the notes stand alone. Restating it exactly is what annotations.nvim does; a restated
heading that matches no prompt is shown as an ordinary annotation, not dropped.

## Chose: The draft link is added by the server, not built into pages
- where: `src/serve.ts`

**Because (Claude, not asked):** built pages are a function of the commit and can't

header as it serves it, while the draft exists. A built site is unchanged.

## Chose: A draft reads the site's places but isn't listed on them
- where: `src/site.ts`
- quote: `ra.place = cx.places.get(placeKey(t));`

**Because (Claude, not asked):** the plan said a built site never contains a draft;
the place pages are built once, so a draft can't appear on them without rebuilding.
Its anchors link a place page when the site has one, and other plans' entries don't
list it under "anchored by."
