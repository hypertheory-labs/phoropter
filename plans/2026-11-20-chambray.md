# `phoropter affected`: the plans that bear on a file, or on a change

Before editing a file, an agent here greps `plans/` for its name, and misses every plan
anchored on a symbol in it. The README had drifted from the plans that changed what it
describes, and nothing said so. Both are the same question asked of the graph
phoropter already builds: which entries are anchored here? `shelf/affected.md` has the
idea (Jeff, after `nx affected`), and the documentation seed needs it.

## Decision: `phoropter affected <file>…` lists every entry anchored in those files
- where: `main.go`
- quote: `func symbols(repo *site.Repo, root, target, at, scheme string) {`

**Because (Jeff, then Claude):** a file anchor matches by path, and a symbol anchor by
the file its definition is in, at HEAD, from the index. So a plan anchored on
`placeFor()` turns up for `internal/site/site.go`, which grep can't do. As-built
entries count too: a `Chose:` anchors code as much as a Decision does.

## Decision: Its output is a lens
- where: `internal/site/lens.go`
- quote: `func ParseLens(source string) *Lens {`

**Because (Jeff, the same morning):** one line per entry, in the reference syntax `Y`
copies, with a note saying where it's anchored (`site.go:212`), so it pastes anywhere
and saves as a lens. It's a snapshot: the lens is yours to prune, and nothing ever
refreshes it. A lens nobody chose the contents of is a smart folder. Ordered oldest
plan first, so it reads as the file's history of reasons.

## Decision: `--out <file>` writes it, and without it, it prints
- where: `main.go`
- quote: `out := fs.String("out", "", "output directory")`

**Because (Jeff, then Claude):** Jeff asked for `-o something-lens.md`. A redirect
would do on a Mac, but Windows PowerShell 5.1's `>` writes UTF-16, which wouldn't read
back as a lens. `--out` is the flag `build` already has, and naming a file is asking,
so phoropter still writes only when asked. It never replaces a file that's there.

## Decision: `--since <ref>` lists the entries a change touches
- where: `internal/site/resolve.go`
- quote: `At               [][]int // the lines each match covers, in order`

**Because (Claude, not asked):** the other half of nx's idea, and the agent's habit
before committing. The change is everything from where it left `<ref>` (their merge
base) to the working tree, uncommitted edits included, since "before I commit" is when
it's useful. Anchors are read at that merge base, so their lines and the diff's are
counted from the same commit. An entry is touched when the diff changes a line it
covers: a quote's matched lines, a symbol's definition, or, for a file anchor with no
quote, any line of the file. A deleted or renamed file touches everything anchored in
it.

## Decision: It's called `affected`
- where: `main.go`
- quote: `case "init", "doctor", "build", "index", "url", "symbols", "ui", "indexers", "guide", "help", "-h", "--help":`

**Because (Claude, then Jeff):** `phoropter why init.go` reads well for one file and
badly for a change (`phoropter why --since main`). `affected` fits both, and it's the
word nx users know. Jeff added the deeper reason: this gives the data that "why"
questions start from, and it shouldn't presume to answer them.

## Decline: Following commits and blame
**Because (Claude, not asked):** "which plan's work last changed this line" needs the
`Plan:` trailers (`shelf/trailers.md`), which this repository has only just started
writing. Anchors are what plans pointed at on purpose, and they're here today.

## Guess: An agent running `affected` before editing finds an entry grep would have missed
**Disproved if:** over the next week of work here, `phoropter affected` on the files
being changed never lists an entry that `grep -l <file> plans/` doesn't.
