# One bad anchor can't stop the site

In the trial's repository, a plan's `- where (new):` held a glob and prose (`*.lens
files in the workspace`) rather than a path. Phoropter makes a page directory for every
anchored place, so it tried to create `files/*.lens files in the workspace/`, and `*`
can't be in a Windows filename. The whole build failed, and the dev server, following
HEAD, stayed at the last commit that built, failing every one after. On a Mac or Linux it
would have made that directory, which is hardly better. The trial's agent found it and
said it plainly: fail the one anchor, not the site.

## Decision: A place whose path isn't a usable file path gets a page that says so
- where: ``scip-go gomod github.com/hypertheory-labs/phoropter . `github.com/hypertheory-labs/phoropter/internal/site`/placeFor().``
- quote: `p = &Place{Key: key, Kind: "file", Label: t.File, Full: t.File, Href: "files/" + t.File + "/"}`

**Because (the trial's agent, then Claude):** the page's address comes straight from the
anchor's text. Now each segment is checked against what every system allows: no
`<>:"|?*` or control characters, no `.` or `..`, no trailing dot or space, none of
Windows's reserved names (`CON`, `NUL`, `COM1` and so on), and not absolute. A path that
fails is still a place, with its page under `files/not-a-path/<slug>/`, the same way a
symbol with no definition is under `symbols/not-at-generated/`. The page shows the text
as written, so the plan's reader sees exactly what was anchored. The same rule on every
system means a site built on a Mac and on Windows has the same pages.

## Decision: The same check applies to a symbol's page address
- where: ``scip-go gomod github.com/hypertheory-labs/phoropter . `github.com/hypertheory-labs/phoropter/internal/site`/placeFor().``
- quote: `href = "symbols/" + def.File + "/" + strings.Join(segments, "/") + "/"`

**Because (Claude, not asked):** a symbol's page address is its file plus its name's
segments, and a name can hold what a filename can't. C# generics put `<` and `>` in
names. When the address fails the same check, the page goes under `symbols/` by the
symbol's slug instead, so an indexer's output can't stop a build either.

## Decline: Making the build skip any page it can't write
**Because (Claude, not asked):** it would have kept the server alive here, but a skipped
page is a broken link with nothing to say why, and the next failure would be just as
silent. The pages' addresses are phoropter's to choose, so phoropter chooses only ones
that can be written.

## Guess: No anchor text can stop a build now
**Disproved if:** any plan's anchor, file or symbol, makes `phoropter build` or the dev
server fail to write a page, on any system.
