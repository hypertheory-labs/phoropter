# What the first repository outside phoropter found

Jeff used phoropter all morning on a .NET course repository, with another Claude, and
that Claude kept notes for phoropter as it went. It's the first time a repository that
isn't phoropter or mock-control has gone from draft to as-built. Most of it worked. What
didn't is small, but each one cost a detour or would mislead the next reader. This plan
takes the notes that are ready.

One note changes the format, and gets its own draft next: how evidence that arrives
after an as-built freezes answers an older guess. The note about whether Decision,
Decline and Guess suit teaching decisions waits for a plan or two in that repository.

## Decision: The dev server follows HEAD
- where: ``scip-go gomod github.com/hypertheory-labs/phoropter . `github.com/hypertheory-labs/phoropter/internal/site`/Serve().``
- quote: `h := &handler{site: s, root: o.Out, repoDir: o.Repo.Dir}`

**Because (the course repo's notes, measured, then Claude and Jeff):** the server builds
once, at the commit where it started. Six commits later, the home page still said "at 6018106", and the
draft page showed a generated commit older than the draft's own `base:`. That reads
backwards, and a reader could take it to mean the repository hasn't moved. It's usually
the agent that starts the server, in the background, so nobody's there to restart it.

On a request, when `--at` is `HEAD` (the default) and HEAD has moved, the server builds
the new commit into a fresh directory, then swaps it in, so no request sees half a site.
It prints a line saying so, and updates the commit in its serving file. A server started
at another commit stays there, since that's what was asked for. HEAD is checked on a
request, at most once a second (Claude, and Jeff agreed): `git rev-parse` costs a few
milliseconds, and a file watcher would rebuild for commits nobody looks at and needs
another dependency.

## Decision: A key menu when the server runs in a terminal, as Vite has
- where: ``scip-go gomod github.com/hypertheory-labs/phoropter . `github.com/hypertheory-labs/phoropter`/main().``
- quote: `signal.Notify(stop, syscall.SIGINT, syscall.SIGTERM)`

**Because (Jeff):** a person running `phoropter` should be able to restart it or get back
to it without remembering commands. After the serving line, it prints `press h + enter
to show help`, as Vite does. The keys:
- `r`: rebuild now, at HEAD
- `o`: open the site in the browser
- `u`: print the address again
- `q`: quit
- `h`: list these

Each key is followed by enter, as Vite does (Jeff chose it): keys alone need the terminal
in raw mode, which changes how every line of the server's output prints and has to be
undone on every way out, including a crash. The menu only appears when stdin is a
terminal. Run in the background, by an agent, nothing reads stdin and nothing changes.

## Decline: Opening the TUI from the server's menu
**Because (Claude, not asked):** a `t` key that runs `phoropter ui` in the same terminal and
returns to the server log on quit is appealing. But the server and the TUI would share
one terminal, and the server's log lines would land on top of the TUI. It waits until
someone wants it enough to work that out.

## Decision: "Nothing defined" says what phoropter can tell
- where: ``scip-go gomod github.com/hypertheory-labs/phoropter . `github.com/hypertheory-labs/phoropter`/symbols().``
- quote: `fail(fmt.Sprintf("nothing defined in %s at %s (uncommitted changes aren't indexed)", rel, repo.Short(sha)))`

**Because (the course repo's notes, measured):** the message blamed uncommitted changes in
two cases where both files were clean. In one, the file lost to a copy with the same
project name, elsewhere in the repository. In the other, it was a `Program.cs` of
top-level statements, which has no names to anchor. The other Claude ran the indexer by
hand to find out. Top-level `Program.cs` is how every new ASP.NET Core app starts, so C#
users will see this often.

The message now says only what's true:
- **The file has uncommitted changes:** say so, as now.
- **A file with the same path below some directory has definitions** (`…/Vendors/Api.cs`
  and `instructor/…/Vendors/Api.cs`): name it, and say that copies with one package name
  are indexed at the first path. It works after copies diverge, which in a course repo
  they do as the session goes.
- **Otherwise:** say the file has no named declarations, as with top-level statements,
  and that a file anchor with a quote reaches it.

## Decision: The indexer guide says how a collapsed copy shows itself
- where: `indexers/README.md`
- quote: `same symbol, the first in path order wins. Never number overloads or otherwise`

**Because (the course repo's notes, measured):** the rule was right and the silence was
the problem. A student's copy of `Software.Api` vanished from `phoropter symbols`,
`missing` was empty, and nothing said why. The guide adds that `phoropter symbols` names
the copy that won, so the reader writing a plan finds out at the moment it matters.

## Decline: An indexer contract field for duplicate packages
**Because (Claude, not asked):** I suggested it first: the indexer would list the paths that
lost. But phoropter can notice from what the indexer already prints, and the roslyn
indexer lives in another repository, so changing the contract means changing it too. If
the message above isn't enough, this is the next step.

## Decline: Telling copies apart, or a `.phoropter-ignore`
**Because (Jeff and Claude):** Jeff raised an ignore file, and it would have handled the
course repo: the student copy wasn't part of the story. Phoropter makes the checkout
with `git archive`, so it could leave ignored paths out before indexing, read from each
commit so older plans resolve as they did. But Jeff's previous course had fourteen lab
starters, each with a `Practice.AppHost`, and there every copy *is* a story. Ignoring
doesn't fit that. Telling copies apart might, but how is a design question with no
repository to try it on. Jeff moved the student copy out, so neither is needed now.

## Decision: `phoropter indexers` lists what this machine can index
- where: ``scip-go gomod github.com/hypertheory-labs/phoropter . `github.com/hypertheory-labs/phoropter`/usage.``
- quote: `phoropter symbols <file> [--scheme <scheme>]`

**Because (the course repo's notes, measured):** nothing the other Claude read said how to
get C# support on a new machine. `indexers/` holds only Go and TypeScript, and the
README names roslyn as an example. One line per indexer: its scheme, its extensions,
its name and version, and where it was found (`indexers/go`, or a path on `PATH`).
With none, it points at the README's indexer list. The organdy as-built's honest miss
(a `go install`ed binary finds no first-party indexers) shows up here too, plainly.

## Decision: The guide's anchors start with what you do, not the grammar
- where: `guide.md › Working with plans › 1. Write the plan › Anchors`
- quote: `Or a symbol, in SCIP's grammar, with the package version written as`

**Because (the course repo's notes, measured, then Jeff):** the other Claude read the
guide, saw "SCIP's grammar" and a `scip-typescript` example, and went looking for
scip-dotnet. The workflow was in the middle of a sentence about schemes. Jeff's view:
if a careful reader got it wrong, the guide should be clearer. The symbol bullet now
says: run `phoropter symbols <file>` and paste a line; you never choose or type a scheme;
`phoropter indexers` says which languages this machine indexes. The grammar is for
people writing indexers, and `indexers/README.md` has it.

## Decision: The guide's citations move to the end
- where: `guide.md`
- quote: `This guide is the format, in the present tense. Each rule names the plan that decided it,`

**Because (the course repo's notes, then Jeff):** on another repository's site, *(lanyard)*
and *(grommet)* are names that mean nothing by design, mid-sentence, with nothing to
click. The rules read fine without them. They keep their history in one closing section,
"Where these rules came from", a line per rule. Jeff wanted them kept, since they show
each rule has a reason, as long as the guide says plainly that they're history: plans
in other repositories, mostly private, and nothing a reader needs to look up.


## Decision: The guide says an answer can become its own decision
- where: `guide.md › Working with plans › Drafts (optional)`
- quote: `(the date is today, the day you say "we're implementing this"), folds each answer into`

**Because (the course repo's notes):** an answer declined a Question's premise and created
new work, and "folds each answer into its entry's reason" didn't cover it. The other
Claude made it a new Decision, which was right. One sentence says so.

## Decision: The agent block says who runs the server, and the guide doesn't need one
- where: `README.md › phoropter › Tell your agent`
- quote: ``guide first: it's at `guide/` on the site (`phoropter url` prints the address), or``

**Because (Jeff):** neither the guide nor the agent block says who starts the server. Jeff
ran it this morning, but usually it'd be the agent. And Jeff saw the catch: the guide is
a page on the server, so it can't be where the agent learns to start the server. Today
the block says "read the guide at `guide/` on the site", which needs a server that may
not be running.

So the instructions live where the agent reads first, the block pasted into its
`CLAUDE.md`: if `phoropter url` finds no server, start `phoropter` in the background and
tell me the address. Following HEAD means one server lasts the session. And the guide
stops depending on a server: it's already built into the binary, so `phoropter guide`
prints it. The block says to read it that way.

## Decision: A draft shows what's already at its places
- where: ``scip-go gomod github.com/hypertheory-labs/phoropter . `github.com/hypertheory-labs/phoropter/internal/site`/anchorHTML().``
- quote: `` place = fmt.Sprintf(` <a rel="anchored-at" itemprop="place" href="%s">%s page</a>`, Rel(here, ra.Place.Href), ra.Place.Kind) ``

**Because (the course repo's notes, and the seed in `shelf/draft-places.md`):** Jeff wants
plans to catch a new one that confuses an old one. A draft is where that's cheapest, and
today it only links each anchor to its place page. Now, under each draft anchor, the
landed entries already there are listed, in the seed's order: guesses not yet answered
(or answered `not tested`, since this work might be the test), then declines, then
decisions. Each is a link with its kind and plan, as microdata, so the agent writing the
draft reads it too. The TUI can show it later; until then the gaps ledger will list it.
A conflict between ideas with no shared anchor still takes a reader.

## Guess: Following HEAD costs nothing a reader notices
**Disproved if:** on phoropter's own repository, with its indexes in the store, the first
request after a commit takes more than 3 seconds, or requests between commits get
measurably slower.

## Guess: The new message finds the copy that won in the course repo's shape
**Disproved if:** in a test with two copies of one package at different paths, diverged,
`phoropter symbols` on the losing copy doesn't name the winning one.
