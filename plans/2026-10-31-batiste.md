# Answer a draft's prompts from the TUI

Ramie (reading the draft) shows a draft's open questions. Answering them takes an
editor that speaks the annotating agreement, and annotations.nvim doesn't answer
prompts yet: Jeff's answers to ramie's prompts landed as ordinary notes, and the draft
page called both prompts unanswered. The TUI is local and can write a file. So it
becomes the first thing that writes answers the way the agreement says. That's for
anyone who doesn't use nvim, and for now for anyone at all.

This is the TUI's first write, and the edge's write ability. It writes the notes file
beside the draft, never the draft, and never the substrate.

## Decision: The annotating agreement is restated here, with phoropter's additions
- where (new): `docs/annotating.md`

**Because (Jeff):** the agreement is part of this work's lineage, not a dependency.
Phoropter restated it for the same reason. The restatement covers what the TUI needs:
the protocol, the notes file, the answer shape for each prompt kind (`**Answer:**`,
`- [x]` and `- [ ]` for a Select, `**Skipped.**`, an optional `**Note:**`), and
phoropter's `**If unanswered:**`. It also covers the `annotates:` line annotations.nvim
writes, which phoropter reads to tell whether the notes are current. It has a worked
example for each kind, so annotations.nvim and the TUI build to one page and can be
checked against it.

## Decision: The TUI writes only `plan.draft.notes.md`
- where (new): `internal/notes/notes.go`

**Because (the agreement):** whoever annotates a file doesn't edit it. A small package
reads a notes file into entries and writes it back. Every entry it didn't make is kept
as written, in order, and an answer goes where its prompt falls in the draft's document
order. Re-answering a prompt replaces that answer and nothing else. A note's heading is a
line number and an author (`## L37 — jeff`), the author from git's `user.name`.

Writing the first note fixes the draft: once notes exist, its author can't revise it
until the notes are deleted, which converting does. So the first answer is a real act,
not a side effect, and the TUI says so once, before the first write: "this fixes the
draft until it converts or the notes are deleted" (Claude, unanswered, so its fallback).

## Decision: It writes only when the draft on disk is the draft on the page
- where: `internal/substrate/model.go`
- quote: `File, ReadAt, SHA256 string`

**Because (Claude, not asked):** the TUI can be pointed at a site it doesn't sit beside.
It finds the repository by walking up to `.git` and the draft by the header's `file`.
It writes only when that file's sha256 is the header's `sha256`. Otherwise it says the
draft changed since this page was read, and `r` reads it again. Whether a local file
matches is a local fact, so it's the TUI's to check. The reasons still come only from
the page.

## Decision: On a prompt row, `a` answers it, in the way its kind asks
- where: `internal/tui/screens.go`
- quote: `func promptDetail(p *substrate.Prompt, w int) string {`

**Because (the agreement):** an Affirm is `y` or `n`. A Select is its options with
`space` to toggle, any number chosen. A Question is text. Any of them can carry a note,
and `s` records a skip on purpose, so "considered and passed" stays different from
"never got to it". After writing, the page is read again, so the prompt shows the
answer phoropter sees. If phoropter doesn't count it as an answer, the TUI wrote it
wrong. A Question's answer, or a note, is written in a text box, and `ctrl+e` moves
what's typed so far into `$EDITOR` when it wants more room. The alternative was always
`$EDITOR` (Claude, unanswered, so its fallback).

## Decision: Any entry can take a free-form note, quoting its heading
- where: `internal/tui/screens.go`
- quote: `func draftRows(d *substrate.Doc, after string) []row {`

**Because (Jeff, then Claude):** a plan is a list of entries, and a note about one wants
to sit beside it. The agreement needs the note's quote to be exact source markdown, and
each entry has an exact, unique line: its heading. On an entry row, `a` writes a note
whose quote is that heading line, copied from `plan.draft.md`, with its line number as
the coordinate. Phoropter puts a note after the entry whose source holds its quote, so
it lands there on the page too. On the draft's About row, `a` writes a note on the whole
draft, with no quote, which the agreement sorts first.

## Decline: Annotating an arbitrary span from the TUI
**Because (Claude, not asked):** quoting a phrase inside an entry means showing the
source markdown and choosing within it, which an editor does better. A note on the
entry says what's needed. Where it has to be the exact phrase, `$EDITOR` and
annotations.nvim are there.

## Decline: Converting the draft from the TUI
**Because (loden):** whoever wrote the draft converts it, usually the agent. The TUI is
the person's side of the protocol.

## Guess: annotations.nvim and the TUI can share one notes file
**Disproved if:** once annotations.nvim answers prompts by `docs/annotating.md`, a notes
file written by one is misread by the other, or by phoropter's draft page.
