# The home page is where an agent starts: what's recent, what's open, where the rest is

Phoropter's own home page lists every plan and every anchored place: 127 items, 55 KB.
Jeff's correction to the first version of this draft: the site is mostly an agent's
surface (the TUI is the person's), so the question isn't what a person sees first,
it's what an agent needs close at hand and easy to locate. A page that size gets
skimmed. Literally: a web-fetch tool hands a large page to a smaller model to
summarize before the agent sees it, so most of those 127 items never reach the agent
that asked.

What does read everything is the TUI, which builds its plan and place lists from the
home page's items. So everything still has a page; it just isn't the home page.

## Decision: The home page is first contact, and short
- where: `internal/site/render.go`
- quote: `<h2>Anchored places</h2>`

**Because (Jeff, then Claude):** an agent arriving at a repository needs to know what
this is, what happened lately, what's still open, and how to ask about code. So the
home page holds:
- one paragraph on what this is, as now
- the recent plans: the most recent day with a plan, and any day within a week of it,
  newest first, each with its as-built and revisits links. A week is "a good start,
  probably enough" (Jeff); on a quiet repository it still shows the last day anything
  happened.
- the open guesses: unanswered, or answered `not tested`, which are what later work
  might test (the "give me a brief" recipe's "what's still open", `shelf/recipes.md`)
- the doors in, one line each: from a place (`phoropter affected <file>`, or any
  file's page at `files/<path>/`), from a change (`phoropter affected --since <ref>`),
  and from a topic (a lens, `lenses/` while served, which an agent makes by meaning
  when asked)
- links to every plan, every file, and every symbol, and to the guide and profile

## Decision: Every plan is listed at `plans/`, every file at `files/`, every symbol at `symbols/`
- where: `internal/site/profile.go`
- quote: ``{`item`, `registered`, `What does this collection hold? From the home page to each plan and anchored place.`},``

**Because (Claude, not asked):** a plan's page is already `plans/<name>/`, a file's is
`files/<path>/`, and a symbol's is under `symbols/`, so the full lists belong at those
directories: an agent can guess the address before it's told. Each list carries the
microdata the home page has now (`plan` and `place` items, linked `rel="item"`), so
nothing a reader extracts per item changes, only where the full lists live. The
profile's `item` says so. The home page's recent plans are `plan` items too, the same
shape, just fewer.

## Decision: The home page links each full list with `rel="index"`
- where: `internal/site/profile.go`
- quote: ``{`collection`, `registered`, `What is this a member of? From a plan or place to the home page.`},``

**Because (Claude, and Jeff left it):** `index` is registered ("an index for the
current page"), so any reader that knows the registry reads it right and phoropter
invents nothing. Jeff's answer to this question was another one: whether now is the
time for serving each repository at `http://localhost:4173/{repo}/`
(`shelf/one-server.md`). It isn't this plan's: every link here is relative, so a prefix
changes none of them, and it's a revisit of batik's server with its own questions (two
clones with one name, `--at`, poplin's quiet background). It's the next draft.

## Decision: The TUI reads its plan and place lists from the `index` links, in this plan
- where: ``scip-go gomod github.com/hypertheory-labs/phoropter . `github.com/hypertheory-labs/phoropter/tui/substrate`/Client#Home().``
- quote: `for _, it := range p.Main.Items("plan") {`

**Because (Claude, not asked):** otherwise the TUI's plan list shrinks to a week the day
the home page changes, and two plans that only work together are a distributed
transaction. It follows every `index` link from the home page and reads the `plan` and
`place` items it finds there, without knowing which list is which, so the profile
stays the only thing it knows. A home page with no `index` links is a site built before
this, and its own items are the whole lists, as before. Its test sites in
`tui/testdata/` are rebuilt, and the golden comparison checks that the old home page's
items are exactly the new lists' items, saying so.

## Decline: Folding the lists with `<details>`
**Because (Jeff):** this draft's first version did that. It helps eyes and nothing else:
the HTML stays 55 KB, and an agent's fetch skims it as before.

## Decline: Pagination
**Because (Claude, then the seed):** "plan 31 of 60" isn't how anyone looks for a plan,
person or agent. Recent, open, and by address are.

## Guess: An agent's first fetch of the home page is enough to start work
**Disproved if:** asked "what's going on in this repository?", an agent reading only
the new home page misses a recent plan or an open guess that the old one would have
shown it.
