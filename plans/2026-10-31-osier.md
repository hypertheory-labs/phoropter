# Line numbers out of the code's text

Phoropter-tui rebuilt its fixtures at selvage's head (selvage put in markup what the
pages said in prose) and answered selvage's guess: six of seven gaps closed, and the
seventh only half. `codeStart` numbers an excerpt, but each line's number is still a
`span.ln` inside the `code` property, so a microdata reader gets the numbers run into
the code. Selvage's as-built is pushed and frozen, so the answer lands here.

## Decision: Line numbers are drawn by a CSS counter, not written into the code
- where: `src/render.ts`
- quote: ``const text = `<span class="ln">${n}</span>${esc(line) || ' '}`;``

**Because (phoropter-tui's brief):** `code` should hold the code. Each line becomes its
own element, and a counter started from the excerpt's first line draws its number in
`::before`. A person sees what they see now; the `code` property's text is just the
lines; copying an excerpt no longer copies its numbers. The brief's other options were
a numbered attribute shown through CSS, or a profile line saying each line starts with
its number; the counter keeps `code` true to its name, and the line number is already a
property, `codeStart`.

## Decision: Two excerpts in one view are ruled apart again
- where: `src/style.css`
- quote: `.view pre + pre { border-top: 1px dashed var(--rule); }`

**Because (Claude, measured):** selvage put a `codeStart` meta before each `pre`, so no
`pre` directly follows another and the rule between excerpts stopped drawing. Nobody
reported it; it showed up reading the stylesheet for this plan.
