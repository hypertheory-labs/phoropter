# Read the draft: phoropter's edge, in the TUI

Loden (phoropter's edge: one draft plan, served live) put a repository's one draft at
`draft/` on the dev server, linked from every page with `rel="draft"`. Today the TUI
reads that page as an ordinary plan. It would show the header's commit as if the draft
were committed, and drop its prompts. Both are wrong in a way a person would believe.
This is also this repository's first plan, and it's a draft on purpose: the TUI should
be able to read the plan that describes teaching it to read drafts.

Reading only. Answering prompts is the next plan.

## Decision: A draft is recognized by its header's `readAt`, not its URL
- where: `internal/substrate/model.go`
- quote: `p.Commit = refOf(it.Get("commit"))`

**Because (Claude, measured):** a draft's main item has `entry` and `title` like a plan,
and may have no prompts, so the main item alone can't tell them apart. The profile's
draft header always has `readAt` and the draft's `sha256`. On that header `commit` is
where the anchors resolve, not what the page was generated from, so a `Page` keeps the
two apart rather than calling both "commit". Deciding by properties, not the URL, is
how the TUI already tells plans from places.

## Decision: The draft opens in plan mode, labeled as a draft
- where: `internal/tui/tui.go`
- quote: `s := newDocScreen(plan, ab)`

**Because (Claude, then Jeff):** the profile says a draft's entries are "as on a plan,"
so one screen reads both, and the keys stay the same. Where a plan's title bar says
`pumice at f02528f`, a draft's says `draft, not committed, read at 15:39 UTC`, with the
anchors' commit after it. A draft has no as-built, so that half of the screen is
empty. Otherwise a draft looks like a plan for now. How it should look is part of an
aesthetics pass later (Jeff).

## Decision: Prompts and annotations are rows after the entry they follow
- where: `internal/substrate/model.go`
- quote: `d.Entries = append(d.Entries, c.entry(e, p.URL))`

**Because (the profile):** a prompt "follows the entry (or intro) it belongs to," and so
does an annotation. The microdata parser groups properties by name, so the TUI recovers
which entry comes before by each item's position in the tree. A prompt row shows its
kind and text, a Select's options, its `fallback`, and its `answer` when the notes have
one. An annotation row shows its heading, its quote, and its comment. A row moves with
`j`/`k` like an entry.

## Decision: The plan list puts the draft first, when the home page links one
- where: `internal/tui/screens.go`
- quote: `for i, p := range s.home.Plans {`

**Because (loden):** every page links `draft/` with `rel="draft"` while the draft exists,
and there's at most one. A row above the plans, marked as a draft, is where a person
looks first. On a built site there's no such link, so there's no row.

## Decision: A key re-fetches the page
- where: `internal/tui/tui.go`
- quote: `case "esc", "backspace":`

**Because (loden, then Jeff):** the dev server re-reads the draft on every request, so
refreshing is the update. The client caches pages, so `r` drops the cache for the
current page and loads it again, keeping the cursor on the same entry when it still
exists. Only `r`, for now (Jeff). Polling and watching the disk were the alternatives.
Watching is a local fact, so it would be the TUI's to do, but the TUI can be pointed at
a site it doesn't sit beside.

## Decline: Answering prompts from the TUI
**Because (Jeff's shelf, then Claude):** writing `plan.draft.notes.md` is the TUI's first
write, and the annotating agreement has to be restated for this repo first, along with
phoropter's `**If unanswered:**`. That's its own plan, once phoropter's brief with the
conventions arrives. This plan never writes a file.

## Guess: A draft page needs nothing beyond the profile
**Disproved if:** while building this, the TUI has to note a new gap on a draft page:
parse prose, lean on a class name, or go without something it wanted.
