# The empty home page says to run `phoropter init`

When phoropter serves a repository with no plans, its home page says that's how every
repository starts, then explains how to write a plan in `plans/` and a draft in
`drafts/`. That was right before muslin. Now a repository's first plan is the one `init`
writes, and this page is the first screen a newcomer sees, so it should say so. It's the
first of what stands between the trial and a newcomer (`shelf/order.md`).

## Decision: The welcome leads with `phoropter init`, and keeps the rest
- where: ``scip-go gomod github.com/hypertheory-labs/phoropter . `github.com/hypertheory-labs/phoropter/internal/site`/home().``
- quote: `<p>A plan is a markdown file in <code>plans/</code>, written before the work: what you decided, what you turned down, and what you're guessing, each with its reason. <a href="%s">The guide</a> says how, starting with “Write the plan.”</p>`

**Because (Jeff and Claude):** "no plans here yet" now has an obvious next step: run
`phoropter init` in the repository, which writes the first plan, "How we work here", as a
draft, shown at `draft/` once it's there. The paragraphs about a plan and a draft stay
after it, for someone who'd rather write their own first plan. This page never says the
pointer or the walkthrough itself: `init` prints those, and a second copy here could
disagree with it.

## Decision: When a draft is up, the welcome says where it is
- where: ``scip-go gomod github.com/hypertheory-labs/phoropter . `github.com/hypertheory-labs/phoropter/internal/site`/home().``
- quote: `<p>When you want to think one through first, put a draft at <code>drafts/plan.draft.md</code>. While <code>phoropter</code> is serving, it's shown at <code>draft/</code>.</p>`

**Because (Claude, not asked):** right after `init`, a newcomer's repository still has
no plans, only the draft. Telling them to run `init` again would be wrong, and `init`
would refuse. So when the dev server has a draft, the welcome links it instead: your
first plan is a draft, here. The dev server already adds a `draft` link to every page as
it serves it (`withDraftLink`), and this is the same kind of change, made in the same
place. A built site never has a draft, so it always says to run `init`.

## Guess: A newcomer goes from the home page to the draft without the README
**Disproved if:** on the trial, after `phoropter init`, Jeff or the fresh agent looks
somewhere other than the home page and `init`'s output to find the draft.
