# As built: gimlet

Built in one session. Nothing needed asking; everything below is a call the plan left
to the builder, or a gap it didn't cover. Run with `npm run dev` (mock-control at
`90c65b9`, beside this repo) or `node src/build.ts <repo> [commit]`.

## Changed: Libraries and layout
- where: `package.json`
- where: `src/scip.ts`
- quote: `const { scip } = require('@sourcegraph/scip-typescript/dist/src/scip.js');`

**Because (Claude, not asked):** the plan left these to the builder. Node 24+ runs the
`.ts` files directly, so there is no build step; `tsc` only checks. `marked` parses
plans and renders prose. The index is read with the protobuf bindings scip-typescript
already ships, a deep import into its `dist`, pinned to 0.4.0. The spike went through
the `scip` CLI and SQLite instead; that's a second binary to install for one lookup,
so I didn't. Modules are one per step: `plan`, `git`, `scip`, `resolve`, `site`,
`render`, `build`, `serve`. The site's URLs are `plans/<cart>/`,
`plans/<cart>/as-built/`, `files/<path>/`, `symbols/<file>/<descriptor>/`, and
`profile/`, with relative links so the output also opens from `file://`.

## Changed: As-built anchors are shown at the as-built's `head`, not the plan's base
- where: `src/site.ts`
- quote: `` const commits = d.before && d.before.sha !== sha ? [d.before, generated] : [generated]; ``

**Because (Claude, not asked):** the plan says each anchor is shown at the plan's base,
but pumice's as-built anchors were written after the work. Its `assets` quote doesn't
exist at the base, so showing it there would make the as-built look wrong. Pumice's
as-built has a `head:` field (not in lanyard), so its anchors are shown at that commit
and at the generated one. Without a `head`, only the generated commit is shown. This
file has a `head` for the same reason.

## Changed: A SCIP anchor's quote is also looked for inside the symbol's range
- where: `src/resolve.ts`
- quote: `` view.note = `lines ${def.startLine}–${def.endLine}; quote at ${describeLines(marked)}`; ``

**Because (Claude, not asked):** pumice's SCIP anchor has a quote, and `MockPanel#`'s
range is lines 9 to 152. Without the quote, a reader can't tell which of 144 lines the
entry meant. The quote's lines are highlighted and the view says whether it was found,
which is how "matches at `da023f1` and not at `90c65b9`" shows up on the page. It's
still not a drift judgment: both sides are shown and neither is marked wrong.

## Changed: A file anchor without a quote is shown, not resolved
- where: `src/site.ts`
- quote: `ra.note = 'no quote, so nothing to search for';`

**Because (Claude, not asked):** pumice's first as-built entry anchors a README heading
path with no quote. The plan's rule is the quote, so there's nothing to search for.
Resolving the heading path itself (walking the markdown headings) was the obvious
alternative; I declined it because the plan chose quotes, and it's a second resolver
for one anchor.

## Changed: Which directories get indexed
- where: `src/scip.ts`
- quote: `return packages.has(JSON.parse(repo.show(sha, f) ?? '{}').name);`

**Because (Claude, not asked):** the plan didn't say, and mock-control's root
`tsconfig.json` has no files of its own. A SCIP symbol names its package, so each
directory whose `package.json` has that name is indexed, using its `tsconfig.json`, or
every `tsconfig*.json` beside it if there isn't one. Commits are indexed only when an
anchor needs them, once each, into a temp checkout from `git archive`. No cache: about
0.4 seconds a commit didn't earn one.

## Changed: Microdata items have no `itemtype`
- where: `src/render.ts`
- quote: `items have no <code>itemtype</code>; property names are defined here`

**Because (Claude, not asked):** microdata wants `itemtype` to be an absolute URL, and
the site has no fixed host, nor a domain I should invent. Items are typed by where they
sit and by their properties, and the profile defines the names. Worth a decision once
there's somewhere real to point.

## Changed: Reverse pages list `where (new)` anchors too
- where: `src/site.ts`
- quote: `ra.place.refs.push({ plan, doc: d, entry: re, anchor });`

**Because (Claude, not asked):** a new anchor still names a file, and pumice's are
mostly in the README. Leaving them off would hide most of what pumice did to that file.
They're marked `new` and not resolved, as the plan says.

## Changed: A cross-repo prefix that names this repo is read as local
- where: `src/resolve.ts`
- quote: `if (cross && cross[1] !== repoName) return { kind: 'cross-repo', repo: cross[1], rest: cross[2] };`

**Because (Claude, not asked):** gimlet's own anchor is `mock-control: plans/...`.
Built against mock-control, that's not another repo. The repo's name is its directory's
name, since mock-control has no remote.
